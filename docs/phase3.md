# Phase 3 — Live reconciliation

Phase 3 adds an in-process Linux watcher to the headless core. Markdown stays authoritative. There is no daemon, watch CLI command, desktop, or sync integration. Hosted CI for this delivery is pending.

## API and lifetime

`Watcher::start(Arc<Library>, WatchOptions)` installs recursive `notify` 8.2.0 observation before the initial content reconciliation. Startup runs synchronously; subsequent work uses an owned worker thread. Embedders should start it off their UI thread. Startup backend registration failures return an error; scan/index failures remain observable in the returned snapshot and are retried by later reconciliation.

`Watcher::snapshot()` returns the latest generation, body-free eligible note IDs/paths/SHA-256 revisions, index status, optional error, and pause state. Generations are local to one watcher lifetime, not distributed sequence numbers. The snapshot can be stale while work is pending or degraded; refetch current disk content before mutation and retain existing revision preconditions.

`subscribe(capacity)` returns a bounded nonblocking subscription. Consume its initial `RescanRequired`, then refetch the snapshot. Drain `try_recv()` during the embedding application's event loop. On every invalidation or generation gap, refetch instead of replaying old deltas. Snapshot publication precedes event publication; deltas at or below an already fetched generation may be ignored. Events include `NoteCreated`, `NoteChanged`, `NoteMoved`, `NoteDeleted`, `DiagnosticsChanged`, `IndexStateChanged`, and `RescanRequired`. A move carries both the old revision/path and current revision/path, including when content also changed.

Subscriber overflow discards queued deltas and leaves a sticky invalidation until consumed. It also requests core recovery once, not an autonomous rescan loop. Capacities are validated; dead subscriptions are removed and subscriber count is capped.

`rescan()` requests asynchronous full recovery; `report_event_loss()` reports an upstream gap. `pause()` requests suspension, discarding hints; an already-running scan may finish. `resume()` re-registers observation before a full pass. `shutdown()` joins the worker and reports worker panics; Drop also joins. In-flight filesystem/SQLite work cannot be cancelled, so shutdown has no hard deadline. Subscriptions become closed when shutdown finishes.

The watcher snapshot reports its own active backend. `Library::status()` on the shared `Arc<Library>` reports whether any of its watcher backends are registered, including multiple watcher lifetimes. Independently opened handles and short-lived CLI processes do not inherit or inspect other handles' registrations; CLI `status` remains inactive.

## Reconciliation and S04 findings

```text
recursive native hints → bounded dirty batch / gap flag
  → cooperative root lock → full disk content scan → SQLite transaction
  → committed body-free snapshot → domain deltas or invalidation
```

The callback never blocks on a full hint queue. Empty/unknown event details, native errors, root changes and queue overflow request recovery. Directory moves/deletes conservatively invalidate the whole library. Access events generated by reading are ignored; writes are never suppressed by a time window. SHA-256 equality prevents self-save duplicate domain changes.

This first implementation hashes/parses the whole library per batch rather than partially scanning dirty subtrees. This deliberately reuses Phase 2's complete identity/unknown-coverage rules. It is bounded in queued work, **not** in corpus memory or scan duration. Defaults are a 75 ms quiet period, 500 ms maximum batching delay, and 30-second safety pass. These are configurable operating defaults, not a measured large-library latency guarantee. Existing 1k/50k Phase 2 benchmarks do not measure watcher throughput; large-corpus tuning remains P7.

No idle database connection or root lock is retained. Busy/index failures preserve the previous snapshot with explicit degraded state. Eligibility loss from permissions, malformed metadata or duplicate IDs is never interpreted as proven note deletion. Recovery publishes invalidation rather than fabricating delete/recreate history. Missing-ID imports are diagnosed, not silently adopted: use explicit `notes init` adoption.

Native registration is retried after gaps/resume and backend failure. Forced periodic/manual passes repair missed content hints, including same-size/same-mtime edits. Observation re-registration precedes recovery scanning to cover the startup/recovery boundary.

## Evidence

Environment: Linux 7.0.0-31-generic x86_64, Rust/cargo 1.93.1, unprivileged UID 1000, temporary libraries on tmpfs. No personal notes used.

- V16: `tests/watcher.rs` exercises a separate Python writer creating nested directories/notes, atomic replacement, directory rename and deletion. `tests/watcher_startup.rs` overlaps an independent burst writer with startup and checks committed change/move/delete event revisions and paths.
- V17: `tests/watcher_recovery.rs` covers atomic bursts with one-slot queues, same-size/restored-mtime edits, sticky subscriber overflow, manual/lost-event/periodic recovery, pause/resume, offline changes/restart, permission loss/recovery, index failure after committed mutation, root removal/recreation, symlink refusal, and shutdown. `src/watcher_tests.rs` deterministically tests same-content reconciliation, initial-invalidation/refetch ordering and one-shot overflow recovery without a native backend, plus a real external edit recovered periodically while every native hint is deliberately dropped. `tests/watcher_status.rs` verifies multiple backend lifetimes on the shared library handle.
- V24 development simulation: duplicate-ID conflict copies remain byte-identical and ambiguous; removing a copy restores eligibility. Delayed updates and temporary disappearance converge. This is not an actual sync-provider or second-device transfer test.

Commands: locked workspace build/tests, formatting, strict Clippy, both existing Python acceptance harnesses, and `git diff --check`. Native watcher tests are included automatically by the existing workspace CI command. Permission tests require an unprivileged user and fail explicitly if run as root.

## External editor and sync boundary

Ordinary in-place and atomic-replacement editors are supported on the tested Linux local filesystem. Temporary disappearance may produce deletion followed by creation; events describe reconciled observations, not every intermediate filesystem action. Duplicate conflict files must be repaired deliberately by the user; the watcher never regenerates IDs or restores files from SQLite.

Keep only Markdown directories under external sync, not Foglio config/cache/locks. Adopt before initial transfer where practical. Cloud placeholders, network filesystems, macOS/Windows backends, suspend/resume of the actual OS, and a real cross-device sync transfer remain unverified. Phase 3 pause/resume and restart tests are not evidence of those release gates.
